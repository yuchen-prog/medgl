## 2. 用户数据检查

用户提供目录含 999 个文件、约 504.57 MiB、没有检测到链接项。数据只读，没有重命名、修改标签或上传到外部服务；日志未输出患者姓名、ID、UID或原始文件名。

针对拒绝原因的匿名核查结果：

- GDCM 文件读取失败 0；切片元信息解析失败 0。
- 常规 CT 的 SOP Class 比较一致 999/999。
- 文件头 Media Storage SOP Instance UID `(0002,0003)` 与数据集 SOP Instance UID `(0008,0018)` 比较一致 0/999。
- 比较已去除合法填充；不是尾随 NUL 或完整/选择性读取差异造成。
- 默认返回 `Inconsistent CT file and dataset identifiers.`；启用显式兼容开关后仅该项不相等被允许，目录/界面保留匿名警告。

标识不一致本身不证明像素一定损坏，也不能自动说明脱敏正确。它可能来自导出/脱敏等处理，实际原因未确定。本次保留严格默认策略，并增加默认关闭的 `--allow-instance-uid-mismatch` 供明确测试。格式错误 UID、错误 SOP Class、重复实例/位置、几何不一致等不被该选项放宽。

合成回归验证默认拒绝、显式兼容解码且强度不变、警告存在，以及兼容模式仍拒绝类型/UID格式/几何错误。原始用户目录的 999 个文件读取前后 SHA256 全部相同，没有改写文件或伪造标识一致性。

真实解码结果：512×512×999，spacing=0.689453/0.689453/0.35 mm，重标定后强度范围 -1024 至 2334。CLI 生成 512×512 PNG，浏览器加载同一序列并显示 1104×783 的非空 CUDA 图像，没有页面错误提示；页面保留 UID 兼容警告。此结果证明当前数据读取/出图链路可用，不代表方位、HU 和临床细节已与可信软件完整对照。

## 4. 性能与短时稳定性

已增加CUDA event kernel计时、主机准备/回读/编码计时及浏览器解码/Canvas提交计时。加载统计区分CPU数据读取、输入检查和GPU资源设置；worker等待截止到worker取任务，不是kernel开始。协议计时字段可选，旧帧兼容；界面仅显示实际帧对应数据。

真实CT的512×512、骨骼预设下，三个视角预览渲染+编码中位数4.18–5.84 ms，精细PNG为41.30–75.46 ms，主要耗时在PNG编码。每情况预热2帧/测12帧，p95按nearest-rank即该组最大值；不是端到端延迟或通用FPS。5轮资源循环复用CPU体，卸载后全局显存跨度0 bytes；不代表进程专属峰值、5次磁盘重读或长期无泄漏。

隔离8082服务完成浏览器5轮CT/phantom切换、12会话、25次滑条变化与离线重连；原生协议用例发送107请求，验证latest-wins最终帧、4个非法请求拒绝、重连及1024²请求/删除竞争后的新会话建立。失败与成功路径均做会话清理，不弱化单场景限制。完整条件、表格、匿名报告及复现命令见 [性能与稳定性基线](MedGL-v1-performance.md)。

上一阶段PNG优化保留原压缩参数、RGB8及颜色元信息，用容量上界预分配避免长度查询的整次压缩。28组模式与2张CUDA合成帧通过libpng/Windows WIC逐字节核查，并与旧PNG完整字节流比较一致；真实CT3视角各20对同RGB的libpng解码错配及最大通道差均0。该阶段新路径渲染+编码中位数28.17–53.24 ms，不能与旧阶段独立运行直接相减；预分配会保留高于实际文件长度的缓冲容量，权衡见性能报告第6节。

本阶段加入显式 `--png-compression fast`，保留全局default，仍不修改DVR算法或JPEG预览。两模式分别通过libpng/WIC像素与非IDAT元信息检查；真实CT512²同RGB配对测20对/视角，快速编码中位数6.626–11.311 ms，RGB错配0但文件增大。776×589真实CT浏览器按默认/快速/快速/默认运行4轮，请求至Canvas中位数依次93.5/70.5/44.5/87.5 ms，文件中位数201783/238455 bytes，运行间波动明显，不承诺固定端到端提速比。原生11/11、前端64项及default/fast各4项完整真实浏览器回归通过；适用范围和复现见性能报告第7节，限速网络未测。
