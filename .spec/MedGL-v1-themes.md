## 1. 操作

右上角月亮/太阳图标切换浅色和深色主题，开关的可访问名称为 `Dark theme`，支持鼠标、触摸与键盘空格操作。默认浅色，不自动跟随系统深色设置；选择深色后刷新或重新打开同一站点会恢复选择。

深色使用中性炭灰底、分层表面和青绿色强调色。页签、侧栏、工具栏、输入框、下拉框、曲线区、直方图、工具提示、错误和回退通知使用统一语义颜色变量。`color-scheme` 同步调整原生表单控件和滚动条；浏览器的 `theme-color` 同步更新。

## 2. 影像与界面的边界

主题仅修改页面的样式与本地偏好，不发送渲染请求，不重建会话，也不改变画布尺寸。相机、窗宽窗位、预设颜色、传递函数、体渲染背景、裁剪盒及玻璃平面均保留。

例如，体渲染背景已经选为白色时，切换深色主题后影像区域仍为白色；需要黑色影像背景时应使用 Display 中的背景色块。渲染背景和界面主题是两个独立设置，不对 CT 像素应用 CSS 反色或滤镜。

颜色预设条、控制点颜色、背景色块、患者方向标记和玻璃辅助面仍保持各自的显示语义，不随界面主题重新着色。PNG 导出仍是服务器缓存的精细图像，不包含任何界面主题或工具层。

## 3. 偏好存储

独立模块 `web/src/theme.ts` 使用 `medgl.theme.v1` 保存 `light` 或 `dark` 字符串，不与本地预设库混存，不保存影像或会话信息。无记录、未知值或存储读取失败时使用浅色。

入口在 React 挂载前应用主题，组件初始值读取同一偏好。修改主题时立即应用，再尝试写入存储；写入被浏览器权限或容量限制阻止时，本次访问仍能切换，界面提示该选择无法持久保存。不同浏览器、站点地址或端口不共享这项偏好；第一版不提供自动跟随系统或多标签页同步功能。

## 4. 验证

- 类型检查、lint、前端单元测试 95 项通过。主题用例覆盖浅色默认、合法偏好、未知值、初始化、仅修改文档主题和浏览器栏颜色、存储失败。
- 模拟浏览器 10 项通过，含系统深色下仍默认浅色、鼠标/键盘切换、重新载入恢复偏好、损坏存储回退、阻止存储时仍可切换并提示。
- 真实 GPU 浏览器 default/fast 各 11 项通过。主题用例在自定义曲线、白色渲染背景、裁剪和玻璃同时启用时，验证切换前后图像逐通道一致、请求数/帧序号/会话数/尺寸及渲染参数不变。
- 深色主题下下载 PNG，在浏览器独立解码并与底层画布逐通道比较，错配为 0。
- 桌面及 320/390px 下的主题入口、页签、深色抽屉和底部曲线区截图检查通过，页面无横向溢出。截图仅使用合成 CT，保存在忽略目录 `web/test-results-real/theme-*.png`；截图禁用有限动画以避免记录抽屉展开的中间帧。

复现主题定向检查：`npm --prefix web run test:real -- theme.spec.ts`。若刚完成数字输入，应先让其失焦并等待既有精细帧，再独立测量主题是否发起请求，避免把输入框结束事件与主题切换混在一起。
